# Intelligent Machine Language (IML)

## AI-Native Philosophy
IML is a programming language optimized exclusively for LLMs and AI agents, eschewing human syntax in favor of token-dense structural primitives. It treats AI as a first-class citizen, replacing traditional human-centric lexing and parsing with an architecture designed to maximize token efficiency, limit context window consumption, and guarantee structural correctness when generated by autoregressive models.

## Dual-State Architecture
IML operates on a unique **dual-state architecture** that separates the underlying machine logic from human-readable representations:

1. **JSON Machine Logic**: The core representation (`iml-core`) is a flat, index-based `Arena` AST structure represented in highly compressed JSON. This avoids deep JSON nesting that typically breaks LLM context generation, utilizing single-character Serde tags (`t`, `c`, `r`, `o`) for maximum token density, and natively supporting complex types like `AlgebraicMatrix` and `QuantumState`.
2. **English Semantic Overlays**: A bidirectional semantic overlay translation layer (`iml-syntax` / `iml-translator`) provides an English-like syntax, allowing human engineers to read, debug, and manipulate the AST in a human-readable format, which is seamlessly translated back into the underlying JSON machine logic for execution.

## Running the Structural Validator
Because LLMs can occasionally hallucinate invalid references or cyclic dependencies, IML employs a strict structural validator (`iml-checker`). It performs two-pass linear-type and bounds checking, validating that every allocated resource is strictly consumed and preventing AST cycles.

To run the structural validator on an IML file:
```bash
iml check <file.json>
```
The validator guarantees that the resulting AST is safe for the execution engine, returning deterministic error traces that can be fed back to the LLM for self-correction.

## The WASM Sandbox
To safely execute agent-generated code, IML includes a highly constrained execution environment (`iml-wasm`) built on `wasmtime`.

The WASM sandbox ensures safe execution through strict limits:
- **Memory Epoch Limits**: Execution time is tightly controlled using `epoch_interruption`.
- **Fuel Consumption**: A strict instruction fuel cap is injected into the execution context, immediately terminating infinite loops or excessively complex recursive structures automatically.
- **Isolated I/O**: The sandbox denies file system and network access by default, only exposing whitelisted capabilities explicitly granted during instantiation.

```bash
# Execute a structurally validated file in the secure WASM sandbox
iml run <file.json>
```

## CLI Commands Reference

```bash
# Run a file in the Wasm sandbox
iml run <file>

# Run the structural validator
iml check <file>

# Translate an IML JSON AST to human-readable format
iml format --to-human <file>

# Translate human-readable format back to IML JSON AST
iml format --to-json <file>

# Export the exact grammar schema for LLM constrained decoding
iml grammar --export json
iml grammar --export gbnf
```
